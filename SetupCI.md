Тесты Playwright можно запускать на любом CI-провайдере. В этом разделе мы расскажем о запуске тестов на GitHub с помощью GitHub Actions.

Чтобы добавить файл GitHub Actions, сначала создайте `.github/workflows` папку и внутри нее добавьте файл `playwright.yml` с приведенным ниже кодом, чтобы ваши тесты запускались при каждом пуше и пул-реквесте для ветки `main`/`master`.

пример кода:
```yaml
name: Playwright Tests
on:
  push:
    branches: [ main, master ]
  pull_request:
    branches: [ main, master ]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v6
    - name: Set up Python
      uses: actions/setup-python@v6
      with:
        python-version: '3.13'
    - name: Install dependencies
      run: |
        python -m pip install --upgrade pip
        pip install -r requirements.txt
    - name: Ensure browsers are installed
      run: python -m playwright install --with-deps
    - name: Run your tests
      run: pytest --tracing=retain-on-failure
    - uses: actions/upload-artifact@v5
      if: \${{ !cancelled() }}
      with:
        name: playwright-traces
        path: test-results/
```

Если посмотреть на список шагов в `jobs.test.steps`, то можно увидеть, что рабочий процесс выполняет следующие действия:

1. Клонировать ваш репозиторий
2. Установить языковые зависимости
3. Установить зависимости проекта и выполнить сборку
4. Установить браузеры Playwright
5. Запустить тесты

---

### **Создать репозиторий и отправить его на GitHub**

После настройки рабочего процесса GitHub Actions вам останется только создать репозиторий на GitHub или отправить свой код в существующий репозиторий. Следуйте инструкциям на GitHub и не забудьте инициализировать репозиторий git с помощью команды `git init`, чтобы вы могли добавлять, коммитить и отправлять свой код.

### **Открытие рабочих процессов**

Нажмите на вкладку Действия, чтобы просмотреть рабочие процессы. Здесь вы увидите, прошли ли ваши тесты успешно или нет.

### **просмотр журналов тестирования**

При нажатии на выполнение рабочего процесса отображаются все действия, выполненные GitHub, а при нажатии на Запуск тестов Playwright — сообщения об ошибках, ожидаемые и полученные результаты, а также журнал вызовов.

### **Просмотр Трасировки**

`trace.playwright.dev` — это статически размещенный вариант средства просмотра трассировки. Вы можете загружать файлы трассировки с помощью перетаскивания.

### **Праивльная работа с секретами**

Такие артефакты, как файлы трассировки или журналы консоли, содержат информацию о выполнении теста. Они могут содержать конфиденциальные данные, например учетные данные тестового пользователя, токены доступа к промежуточному серверу, исходный код для тестирования, а иногда даже исходный код вашего приложения. Обращайтесь с этими файлами так же бережно, как с конфиденциальными данными. Если вы загружаете отчеты и трассировки в рамках рабочего процесса непрерывной интеграции, убедитесь, что вы загружаете их только в надежные хранилища артефактов или шифруете файлы перед загрузкой. То же самое касается обмена артефактами с членами команды: используйте доверенный файловый ресурс или шифруйте файлы перед отправкой.
